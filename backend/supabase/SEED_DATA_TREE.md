# 더미 데이터 "내 강의" 트리 구조

`seed.sql`로 넣은 데이터를 계정별·모드별로 "내 강의" 페이지에 들어갔을 때 보이는 트리 구조로 정리한 문서입니다.

- **강의자 모드**: `created_by = 나` AND `created_mode = 'lecturer'`인 노드만 보임
- **수강생 모드 - 내가 만든 폴더**: `created_by = 나` AND `created_mode = 'student'`인 노드
- **수강생 모드 - 즐겨찾기**: `my_nodes`에 등록한 남의 강의/폴더. 즐겨찾기는 **강의자 모드로 만든 노드만** 등록 가능(RLS로 강제, 남의 수강생 모드 개인 정리 폴더는 즐겨찾기 대상이 될 수 없음). `folder_id`가 있으면 "내가 만든 폴더" 밑에 끼워 넣어 보여주고, `folder_id`가 `null`이면 최상위에 표시

각 항목엔 `(내 것)` / `(즐겨찾기, 실제 만든 사람)`을 표기했습니다.

## 정리: 즐겨찾기 관계 요약

| 즐겨찾기한 사람 | 대상 | 실제 만든 사람 | 실제 parent | 내 폴더 어디에 정리했나 |
|---|---|---|---|---|
| A | 배열과 연결 리스트 (강의) | B | 운영체제 | 컴퓨터 과학 › 자료구조 |
| A | AI 세미나 (강의) | B | 운영체제 | 최상위 |
| A | 파이썬 워크샵 (강의) | B | 운영체제 | 최상위 |
| A | 커리어 토크 (강의) | C | 수학 | 최상위 |
| A | 수학 (폴더) | C | (최상위) | 최상위 |

즐겨찾기 대상(`node_id`)의 실제 `parent_id`는 원래 만든 사람(B/C)의 트리 구조 그대로이고("실제 parent" 컬럼), "내 폴더 어디에 정리했나"는 A 본인의 `my_nodes.folder_id`에만 저장되는 개인적인 값입니다 — 남의 트리 구조를 바꾸는 게 아닙니다.

## 이전 버전과 달라진 점

원래는 B/C가 `운영체제`/`수학` 폴더를 **수강생 모드**로 만들어서 A가 즐겨찾기하는 구조였는데, 즐겨찾기는 강의자 모드로 만든 노드만 등록 가능해야 하므로(RLS 정책 `my_nodes_only_favorite_lecturer_mode_insert`/`_update` 참고, `DB_DESIGN.md`) 이 규칙 위반이었습니다. `운영체제`/`수학`을 강의자 모드 폴더로 바꾸고, B/C의 강의들을 각각 그 밑으로 옮겨서 바로잡았습니다. B/C는 수강생 모드로 만들거나 즐겨찾기한 게 하나도 없는 상태를 유지합니다.
